How it works
  • Choose seconds or milliseconds when entering a Unix value.

Common uses
  • Reading database and API timestamps.
  • Creating an exact expiry time for a test.
  • Comparing local time with UTC during incident analysis.

  1. Convert Unix timestamp 0 to inspect the epoch, then compare a current timestamp in seconds and milliseconds.

Tips for a reliable result
A seconds-versus-milliseconds mismatch produces a very different date. Check the unit used by the source API before converting.

Questions and troubleshooting
What is Unix time?
Unix time counts elapsed seconds from 1970-01-01 00:00:00 UTC. Many JavaScript APIs use milliseconds instead.
How are time zones handled?
A Unix timestamp identifies one instant. The tool shows that instant in UTC and your browser’s local zone. Date input is interpreted according to the option you choose.
When a timestamp shows an unexpected date
Confirm whether the source uses seconds or milliseconds and whether you are reading UTC or local output. The device timezone affects local values. Out-of-range numbers and invalid calendar input need correction before conversion.
Why do UTC and local time show different hours?
They display the same instant using different timezone rules. Share the UTC value or an explicit timezone when communicating timestamps between systems.
Does the tool fix a wrong system clock?
No. Local time displays and comparisons depend on the device and browser. Confirm your device clock and the source timestamp unit when results look unexpected.
