Choose a destination you can maintain

A QR code is only as useful as the destination it represents. Before generating one for a leaflet or label, open the intended URL and check that it is public, works on a phone, and does not require your own logged-in session. Prefer a stable HTTPS destination that you control or have permission to use.

The Anvil Tools generator creates a static code from the entered text or URL. It does not provide a hosted redirection service, scan tracking, or an editing dashboard for printed codes. If you encode a URL directly and later need to change it, the code itself still contains the old URL. A redirect you maintain on your own site is a separate website feature.

Generate a short, recognizable test

  1. Paste the final destination and inspect its spelling.
  2. Generate the code and scan the screen with a phone.
  3. Inspect the address shown by the scanner before opening it.
  4. Download the PNG, then test that downloaded image.
  5. Place the image in the intended design and make a sample print.

A long URL or large block of text produces a denser pattern and may fail if it exceeds the generator's capacity. Start with a short, direct destination where possible. Do not remove required query parameters without checking the resulting URL. A generator success message confirms creation, not that every scanner will read the final design.

Protect contrast and clear space

The current tool produces a dark pattern on a white background at 180 by 180 pixels. Keep it crisp and avoid stretching the image into a rectangle. Preserve clear light space around the pattern in the final design. Text, decorative borders, cropping, and a busy photograph immediately against the code can interfere with scanning.

A small PNG can become blurry when enlarged by a document editor or print workflow. Inspect the exported document, not just the editor's view. Avoid smoothing, artistic filters, or placing a logo over the pattern. This generator does not provide a custom logo or vector export workflow.

Test the real size and surface

Print a sample at the size a reader will encounter. Test at a normal viewing distance and in the lighting expected at the location. A glossy label, curved bottle, dim hallway, or distant poster can behave differently from a bright computer screen. Use more than one phone if the code will be widely distributed.

There is no single print size that guarantees success for every pattern, device, distance, and surface. Increase the usable size or reduce the encoded content if the sample is difficult to scan. Keep the destination readable as ordinary text beside the code where practical so readers have another way to reach it.

Before distributing a batch

Verify the final exported file and a physical sample from the printer. Open the destination on a phone and check the actual task: reading a menu, reaching a form, or downloading a public document. Avoid including private access links or credentials in a code. Once printed, it can be photographed and shared by anyone who sees it.

Keep a copy of the final destination, design, and test result. If the page changes later, revisit the physical code to confirm that the reader's journey still works.
